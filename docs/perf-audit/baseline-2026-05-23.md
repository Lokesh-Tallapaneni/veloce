# Perf audit baseline — 2026-05-23

Reproducibility: Windows 10, Python 3.13.6, veloce 0.1.0, fastapi 0.115.12,
flask 3.1.1, uvicorn 0.34.2, httpx 0.28.1, single worker, stdlib asyncio
loop (no uvloop on Windows), seed=42, concurrency=8, duration=4s, runs=3.

## End-to-end (`bench/comparative`)

`json-hello` (median of 3 runs):

| framework | rps    | p50 us | p99 us | errors |
|-----------|-------:|-------:|-------:|-------:|
| veloce    |  1,320 |  5,844 |  7,643 |     0  |
| fastapi   |  1,288 |  5,943 |  7,874 |     0  |
| flask     |    824 |  4,688 |  6,532 |     0  |

veloce beats fastapi on rps + p50 + p99. veloce loses p99 to flask.

`path-param` (median of 3 runs):

| framework | rps    | p50 us | p99 us | errors |
|-----------|-------:|-------:|-------:|-------:|
| veloce    |  1,267 |  6,013 |  8,518 |     0  |
| fastapi   |  1,243 |  5,966 |  8,038 |     0  |
| flask     |    828 |  4,757 | 11,000 |     0  |

veloce beats fastapi on rps. veloce loses p50 and p99 to fastapi by ~50 us
and ~480 us respectively — that gap is the audit target for path-param.

## In-loop dispatch (`bench/hot_dispatch_bench` — 50k iters, 5k warmup)

| case            | rps    | us/req |
|-----------------|-------:|-------:|
| static GET      | 28,545 |  35.03 |
| path-param GET  | 28,393 |  35.22 |
| POST 64 body    | 24,799 |  40.32 |

These isolate framework dispatch from httpx/uvicorn/loop overhead. End-to-end
p50 (~5.8 ms) is dominated by client + loop; framework work is the ~35 us
slice. Per-file wins land here first and bubble up to end-to-end only after
many us of shaving.

## Walk order for the per-file audit

In profile-hotness order: app.py → routing/router.py → http/response.py →
http/request.py → dependency.py → helpers.py (touched via `g._reset`) →
signals.py (touched via `has_receivers_for`) → http/datastructures.py
(touched via Headers under request init) → encoders.py / json_provider.py
(touched only if response is JSON-coerced) → everything else as cold sweep.
