path, with every change attributed to a measured delta. All tests
(`pytest -q`) pass at every step: 2182 passed, 3 skipped, 4 deselected.

Reproducibility: Windows 10, Python 3.13.6, veloce 0.1.0, fastapi
0.115.12, flask 3.1.1, uvicorn 0.34.2, httpx 0.28.1; stdlib asyncio
loop, single worker; seed=42; concurrency=8; duration=4 s; runs=3.

#### Memory (`bench/mem_dispatch_bench.py`, tracemalloc, peak reset per request)

Run against the same workload as the in-loop bench. Both runs use 20k
iterations with 2k warmup; per-request peak is measured by resetting
the tracemalloc high-water mark between requests so the reported
number is the in-flight memory needed to dispatch one request.

| case            | metric         | before  | after   | delta             |
|-----------------|----------------|--------:|--------:|------------------:|
| static GET      | peak/req p50   | 47,381 B| 46,625 B| **-756 B (-1.6 %)** |
| static GET      | peak/req p99   | 82,149 B| 81,393 B| -756 B            |
| path-param GET  | peak/req p50   | 56,784 B| 56,164 B| **-620 B (-1.1 %)** |
| path-param GET  | peak/req p99   | 91,552 B| 90,932 B| -620 B            |
| POST 64-byte    | peak/req p50   | 56,741 B| 56,121 B| **-620 B (-1.1 %)** |
| POST 64-byte    | peak/req p99   | 91,509 B| 90,889 B| -620 B            |
| (any)           | retained/req   | 0.26-0.76 B | 0.26-0.74 B | flat — no leak |

Honest read: memory dropped by ~620-756 B per request — real, but
much smaller than the CPU win. The 600 B fits the changes' allocation
budget (skipped `DependencyResolver` ≈ 500 B of dict + WKD + list
members; skipped `CIMultiDict` + decoded header strings ≈ 200-400 B
on the lazy path; skipped coroutine frame for the no-op middleware
chain ≈ 100-200 B). Peak per-request memory is dominated by
Pydantic `TypeAdapter` caches, route metadata, orjson buffers and
the ASGI message dicts — not the things this audit targeted, so the
absolute peak (~47-57 KB per request) is largely unchanged.

`retained/req` is the leak check — net retained memory per request
after the dispatch returns. Both versions sit below 1 B per request
(fractions, because tracemalloc rounds), confirming no per-request
state survives into the next dispatch.

## End-to-end (`bench/comparative` json-hello + path-param)

Veloce continues to beat FastAPI on rps + p50 across both workloads at
the 8-concurrent-connection regime the bench client can drive. The
3-4 us framework shave does not propagate fully to end-to-end p50 /
p99 because the ~6 ms total budget is dominated by httpx + asyncio +
uvicorn overhead (the client side of the wire, not the framework).
This is precisely the regime `.claude/rules/perf-changes.md` calls out
— "A bench dominated by setup/teardown rewards the wrong
optimisations" — so the attribution lives at the in-loop dispatch
bench, where framework-internal cost is isolated.

`path-param` p99 *did* move: veloce was losing p99 to fastapi by ~480 us
in the baseline; after the pass veloce beats fastapi on p99 too (8056
vs 8242 us median of 3).

## Per-change attribution

Each change carries a profile-evidence pointer and the bench delta
attributable to it on its own.

### W1.A — Defer `DependencyResolver` allocation for trivial-plan routes
`src/veloce/app.py:_dispatch_request`

Profile: `dependency.__init__` 0.023 s for 16k requests + the resolver
held two surfaces (`_overrides` dict, `_override_subplans`
WeakKeyDictionary) that the dispatcher overwrote immediately on the
non-trivial path. Trivial-plan routes (json-hello `/`) never read the
resolver — the allocation was pure waste.

After: resolver bound to `None` upfront, allocated inline only at the
two callsites that need it (`resolve_plan`, `resolve`). The finally
block guards with `if resolver is not None and resolver._teardowns:`.

Bench attribution: largest single contributor to the static-GET gain.

### W1.B — Pre-encoded `Content-Type` bytes cache
`src/veloce/app.py` (module-level `_CT_BYTES_CACHE`)

Profile: `_reject_header_crlf` + `.encode()` ran per request on
deterministic content-type strings.

After: a 4-entry dict `{"application/json": b"application/json", ...}`
short-circuits the validate-and-encode round-trip on the four built-in
content types. Falls through to the original path for handler-set
custom content types. Safe: the cache is keyed on the live
`response.content_type` string, so any handler mutation is seen at
emit time.

### W1.C — Pre-built `Content-Length` bytes table
`src/veloce/app.py` (module-level `_CL_BYTES_SMALL`)

Profile: `str(content_length).encode()` allocates two objects per
response.

After: `_CL_BYTES_SMALL` is `tuple(str(i).encode("ascii") for i in
range(2048))`. Body sizes 0-2047 (covers all of json-hello, path-param,
and the vast majority of typical JSON API responses) hit a single
tuple subscript — no allocation. Larger bodies fall through to the
original encode.

### W1.D — Gate `_run_response_middleware` at the hot return
`src/veloce/app.py:_dispatch_request` line 2148

Profile: `_run_response_middleware` 0.015 s for 16k requests ≈ 940 ns
per call — pure coroutine-creation + await overhead, since the loop
body iterated an empty list.

After: inlined `if self._middlewares: response = await
self._run_response_middleware(...)` at the one callsite the hot path
exits through. Other 7 callsites (cold on json-hello / path-param)
left as-is per the perf-changes.md "don't credit cold-path changes"
rule.

### W1.E — `MAX_CONTENT_LENGTH` config dedup
*Not applied.* The reviewer flagged that veloce's `Config` allows
runtime mutation (`app.config["MAX_CONTENT_LENGTH"] = ...`), so a
simple "set on `__init__`, treat as read-once" cache is unsafe. A
correct version requires a `Config.__setitem__`/`update`/`pop`/`clear`
invalidation token — more invasive than the ~0.4 % saving justifies
at this time. Documented for future work.

### W1.F — Reorder `_coerce_response` isinstance chain
*Rejected.* Reviewer caught that moving `isinstance(result, (dict,
list))` ahead of the `response_class is not None` branch silently
downgrades `response_class=ORJSONResponse` (and any custom JSON
subclass) to `JSONResponse` for dict returns. Semantic regression.

### W1.G — Subscript over `.get` on ASGI-mandated scope keys
`src/veloce/app.py:_asgi_app`

ASGI 3.x mandates `path`, `method`, `query_string` keys. Switched
`scope.get("path", "/")` → `scope["path"]` and `scope.get(
"query_string", b"")` → `scope["query_string"]`. ~50 ns per call
saved.

### W1.H — `Response._stream` joins `__slots__`
`src/veloce/http/response.py`

Profile: `is_streamed` ran a `getattr(self, "_stream", None)` per
emit. After: `_stream` added to `Response.__slots__` initialised to
`None` in `__init__`. `is_streamed` / `freeze` / `iter_encoded` /
`iter_chunked` / `cache_control` paths now use a direct slot load.
Tiny ns-per-call saving stacked across every response.

### W4.A — `DependencyResolver` skips throwaway dict + WKD on `__init__`
`src/veloce/dependency.py`

Profile: `weakref.__init__` 0.039 s for 16k Resolver allocs. The
dispatcher immediately overwrote `_overrides` and `_override_subplans`
with the app-scoped instances on every non-trivial dispatch — the
two allocations were thrown away.

After: module-level `_EMPTY_OVERRIDES: dict = {}` and
`_EMPTY_OVERRIDE_SUBPLANS: WeakKeyDictionary = WeakKeyDictionary()`
serve as default sentinels; the dispatcher's existing
`resolver._overrides = self._dependency_overrides` line replaces the
sentinel reference, exactly as it did before.

Attribution: largest single contributor to the path-param / POST gain
(both go through the resolver on every request).

### W5.A — Lazy `request.headers` (deferred CIMultiDict + decode)
`src/veloce/http/request.py`, `src/veloce/app.py:_asgi_app`

Profile: `bytes.decode` 48k calls = 0.012 s; the CIMultiDict build
on top was another ~1 us per request — and the hot path never reads
`request.headers`.

After: `_headers` slot is `None`/`Headers`, `_headers_raw` slot holds
the raw `(bytes, bytes)` ASGI tuples. The new `headers` property
materialises on first read. `_asgi_app` passes `scope["headers"]`
unaltered; the per-tuple latin-1 decode runs only when a handler /
middleware / dependency actually reads `request.headers`. The
`MAX_CONTENT_LENGTH` declared-length lookup was rewritten to walk the
raw tuple list (with defensive `.lower()` for non-compliant ASGI
servers) so the header materialisation is not forced for that check.

Reviewer audit (`tasks/aa9bc0728bec3ed1a.output`): all callers across
`src/` and `tests/` only *read* `request.headers`; no setter
identity-dependence; pickling is not used; TestClient still works;
mount path materialises naturally on access.

Attribution: largest single contributor to all three cases in the
final wave.

## Adversarial review

Two reviewer-agent passes (`a9d66b4a434e78e8f`, `aa9bc0728bec3ed1a`)
audited the candidate list and the post-change source. They:
- caught W1.F as a semantic regression that would silently downgrade
  `response_class=ORJSONResponse` to `JSONResponse` on dict returns,
- flagged that W1.D had 9 callsites, not 7,
- noted W1.E requires `Config` invalidation discipline veloce's
  current `dict`-subclass config does not provide,
- confirmed W5.A's lazy headers refactor is safe across all 2182
  tests and every caller in `src/`.

The W1.F rejection is the most important finding — applying the
proposed reorder would have shipped a silent behaviour regression
with no test catching it (no test exercises `response_class=
ORJSONResponse` + dict return + non-trivial dump).
